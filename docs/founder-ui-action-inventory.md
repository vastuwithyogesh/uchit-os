# Founder UI action inventory

This is the source-controlled control map for the Founder Edition. It is an operator audit, not a deployment approval. Every protected mutation must still be accepted or rejected by `POST /api/actions` (or the protected case-file/report route); a disabled button is only an affordance and is never the security boundary.

## Shared interaction contract

All mutation surfaces use the shared `busy` guard, stable idempotency key, organisation/case/global revision tokens, and an `aria-live` result region. A successful write refreshes the scoped bootstrap/state before presenting the next step. A 400 is a validation correction, 401/403 is an authentication/permission recovery, 404 is a scope recovery, 409 preserves the draft and asks the operator to reload/reconcile, 428 preserves the draft and asks for a fresh concurrency token, and 500/503 preserves the draft while directing the operator to retry or System Check. Uploads are private case-file assets; evidence refs are opaque and never exposed as public URLs.

## Deliberately blocked controls

`components/spatial-workspace.tsx` exposes a disabled “Computed 16D mapping is deferred” control only as an explicit methodology status; it has no mutation handler by design. Client portal routes, preview direct object URLs, public report delivery, Lovable sync/import/webhooks, computed 32D/16D geometry, unapproved site scoring, and Stage B remedy selection remain server-blocked and are listed in `lib/founder-staging-walkthrough.ts`. Client delivery is disabled during Founder Edition.

## Manual walkthrough evidence

For a two-floor rehearsal, upload two different plan bytes and two different full-colour hand-marked sheet bytes, bind each to its own floor and current plan version, and confirm each manually. A matching checksum or reused evidence ref is a failed walkthrough even if the UI accepts the selection. Use only synthetic staging fixtures until the owner explicitly approves real files.

## Audit boundary

The inventory is intentionally source-level and deterministic. It does not claim browser E2E coverage. The companion contract test checks action allowlisting, revision/idempotency presence, blocked controls, native navigation, accessible status regions, touch/focus CSS, and private report/client-delivery routes.
