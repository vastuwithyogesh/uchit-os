# Uchit Vastu Resource Governance

Last reviewed: 2026-08-10

## Authority order

1. `Uchit_Vastu_India_Company_Playbook_v1.pdf` governs the client journey, operating roles, pipeline, privacy and delivery discipline.
2. `Uchit_Vastu_India_Brand_Identity_Report.pdf` governs brand identity, visual language, terminology and logo usage.
3. The v2 existing-space and new-construction documents govern the latest technical service structure. Commercial amounts, visits, revisions and SLAs remain proposal-configurable until formally approved.
4. `Uchit_Vastu_Optimized_Spatial_Analysis_Workbook.pdf` governs observation, placement, priority and implementation tables.
5. `Uchit_Prakriti_4_37 onwards.pdf` governs only the optional personal Prakriti instrument.
6. Editable DOCX files are report-template sources, not independent policy authorities.
7. PNG samples and v1 documents are visual/legacy references. They do not override the authorities above.

## Product principles

- Use the full name **Uchit Vastu India** where brand recognition is needed.
- Promise clarity, structured assessment and practical recommendations; never promise miracles, financial outcomes or guaranteed life results.
- Keep the interface calm and minimal: architectural ivory, black, charcoal and restrained antique brass.
- Use Inter for interface text and data. Use the approved editorial serif only for selective branded headings.
- Use a flat approved horizontal logo in the product header. Do not use embossed, textured, glowing or gradient logo mockups.
- Every open lead or case must have one owner, one current status and one dated next action.
- Use one canonical seven-stage service model: Understand, Verify, Map, Evaluate, Prioritise, Recommend, Implement.
- Present a simpler client journey: Information needed, Verification, Assessment, Review, Action plan, Follow-up.
- Keep existing-space and new-construction workflows separate. New construction requires drawing versions, review rounds, checkpoints and pre-freeze gates.
- Do not invent a numerical Vastu score. Use explainable categorical findings with evidence and versioned rules.
- Keep Prakriti, personal birth details, Muhurat, planet or numerology modules optional, separately consented and separately permissioned.

## Canonical workflow

The commercial journey is:

Opt-in -> VSL -> setter contact -> paid Private Review Call -> preparation form -> review call -> consultation scope and payment -> onboarding -> assessment and delivery -> follow-up -> permission-based testimonial/referral.

The internal lead pipeline is:

New -> Contacted -> VSL Sent -> VSL Watched -> Paid Review Pending -> Paid Review Booked -> Form Pending -> Review Completed -> Qualified -> Proposal/Scope -> Won -> Onboarding -> In Delivery -> Follow-up -> Closed/Referral.

The delivery workflow is:

Case setup -> document collection -> verification -> assessment -> recommendation design -> senior QA -> presentation -> approved written report -> implementation support -> success review.

## Data model additions

- Contact preferences, WhatsApp number, language, call window and versioned consent records.
- Decision-maker status, other decision-makers, client vision, urgency, fit outcome and disqualification reason.
- Service type, property status, area/unit, floors, site coordinates, access, current use, constraints and project stage.
- Versioned input assets with floor, drawing revision, received/verified timestamps, verifier, discrepancy and superseded status.
- Project-team roles including architect, structural, MEP, interior and contractor contacts.
- Versioned commercial scope with line items, taxes, included visits, revisions, review rounds, checkpoints and support windows.
- Structured observations, recommendations, implementation tasks, clarification logs, review rounds and checkpoints.
- Separate enums for assessment status, attention class, decision priority, implementation horizon and implementation status.

## Report architecture

1. Executive summary and client objective.
2. Agreed scope, verified inputs, assumptions and drawing versions.
3. Method and rule/template version.
4. Findings and evidence-backed report card.
5. Annotated recommendations and acceptable alternatives.
6. Prioritised implementation plan with owner, feasibility and target date.
7. Responsibilities, limitations and professional disclaimers.
8. Optional, versioned appendices such as the space-use and placement guide or consented Prakriti results.

Every final report must retain immutable artifact, evaluation and template hashes, approval evidence and release history.
